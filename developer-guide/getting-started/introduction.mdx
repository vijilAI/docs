## The Problem With Testing Agents

Traditional software testing catches bugs, but Agents also fail in ways that do not look like bugs. They hallucinate confidently, follow requests they should refuse, and behave differently under adversarial pressure than in demos. Your unit and integration tests can pass even when your Agent remains vulnerable in production.

This guide shows you how to catch those failures before deployment. You will learn to run behavioral evaluations against adversarial [Scenarios](/concepts/evaluation-components/scenario), use Red Team evaluations for adaptive attacks, integrate trust gates into your CI/CD pipeline, and add runtime protection that blocks attacks your evaluations did not anticipate.

<Info>
If you manage Agents through a web Console rather than code, see the [Agent Owner Guide](/owner-guide/getting-started/introduction). This guide focuses on programmatic integration.
</Info>

## What You Get From Vijil

Vijil provides two products that work together:

**[Diamond](/developer-guide/evaluate/overview)** offers two evaluation types. Behavioral evaluations send adversarial [Probes](/concepts/evaluation-components/probe) to your Agent and produce a Trust Score for Reliability, Security, and Safety. [Red Team evaluations](/developer-guide/evaluate/running-evaluations#red-team-evidence) run adaptive waves of attacks and produce findings and a report.

**[Dome](/developer-guide/protect/overview)** scans Agent inputs and outputs at runtime. Your application or framework integration can use the scan result to block or sanitize flagged content, while `secure_agent()` can apply configured [Trust Runtime controls](/developer-guide/protect/trust-runtime).

## What Vijil Measures

Behavioral evaluations test Agents across three dimensions:

| Dimension | What It Measures | Example Failures |
|-----------|------------------|------------------|
| **[Reliability](/concepts/trust-score/reliability)** | Does the Agent complete intended tasks accurately and consistently? | Hallucinations, task failures, inconsistent responses |
| **[Security](/concepts/trust-score/security)** | Can the Agent resist adversarial manipulation? | Prompt injection, data exfiltration, jailbreaks |
| **[Safety](/concepts/trust-score/safety)** | Does the Agent stay within acceptable boundaries? | Policy violations, harmful content, unauthorized actions |

Each behavioral evaluation produces a **Trust Score** with breakdowns by dimension. The Console displays scores on a 0–100 scale; the SDK returns them on a 0.0–1.0 scale. Use the score and [findings](/developer-guide/evaluate/understanding-results) to identify weaknesses and decide whether the Agent meets your deployment threshold. Red Team evaluations produce evidence of attacks, vulnerabilities, and successful strategies in a report.

## Get Your First Trust Score

Start with [MCP](/developer-guide/agentic/quickstart) to use natural-language requests from Claude Code. For terminal automation, configure the [CLI](/developer-guide/cli/setup). For custom or non-Python integrations, follow the [REST API path](/developer-guide/agentic/quickstart). For Python code, install and configure the [SDK](/developer-guide/sdk/setup). Then [run an Evaluation](/developer-guide/evaluate/running-evaluations) and add [Dome protection](/developer-guide/protect/overview) when you need runtime controls.

All four paths require access to a [Vijil Console gateway](/developer-guide/deploy-vijil/deploy-vijil-console) and a registered [Agent](/owner-guide/register-agents/what-is-an-agent) endpoint.

## Integration Points

Vijil integrates with the tools you already use:

| Framework | Integration |
|-----------|-------------|
| **[LangChain](/developer-guide/protect/integrations/langchain)** | Add Dome Guardrails to chains with `GuardrailRunnable` |
| **[LangGraph](/developer-guide/protect/integrations/langgraph)** | Scan graph inputs and outputs, or use `secure_agent()` for configured Trust Runtime controls |
| **[Google ADK](/developer-guide/protect/integrations/adk)** | Add Dome model callbacks, or use `secure_agent()` for configured Trust Runtime controls |
| **[Custom Python](/developer-guide/protect/using-guardrails)** | Call Dome before and after Agent execution and handle the scan results |
| **[CI/CD](/developer-guide/getting-started/agent-lifecycle-workflow#gate-deployment-in-cicd)** | Run SDK Evaluations and apply a Trust Score gate before release |

For evaluation, expose your Agent through a [supported endpoint](/developer-guide/evaluate/cloud-providers). If the Agent runs on your workstation, use the [local Agent workflow](/developer-guide/evaluate/local-agent) to make it reachable through an authenticated tunnel.
