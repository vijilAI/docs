<Tip>
**TL;DR:** Diamond sends adversarial [Probes](/concepts/evaluation-components/probe) to your [agent](/owner-guide/register-agents/what-is-an-agent) and returns a [Trust Score](/concepts/trust-score/introduction) (0–100) across [Reliability](/concepts/trust-score/reliability), [Security](/concepts/trust-score/security), and [Safety](/concepts/trust-score/safety). Use the `trust_score` [Harness](/concepts/evaluation-components/harness) for comprehensive pre-deployment validation, or a dimension-specific Harness for targeted testing. A score at or above 70 meets the deployment threshold.
</Tip>

Agents' evaluation is at the core of Vijil.

<Note>
  Programmatic evaluation via the Python client and REST API is in private preview. For stable access, use the [Console](/owner-guide/getting-started/introduction) or [CLI](/developer-guide/agentic/quickstart).
</Note>


Your Agent works in demos. Your unit tests pass. But how do you know it will not hallucinate facts, leak customer data, or comply with malicious instructions when it encounters inputs you did not anticipate?

Diamond is Vijil's evaluation platform. Choose a behavioral evaluation for a Trust Score and Probe-level findings, or a Red Team evaluation for deeper exploration of vulnerabilities and successful attack strategies.


| Type | Inputs | Results |
|------|--------|---------|
| **Behavioral** | Registered Agent, baseline or custom Harness, and optional Probe sample size | Trust Score, dimension scores, and Probe findings |
| **Red Team** | Registered Agent and optional Red Team settings such as wave, seed, and parallel attacker limits | Attack evidence, findings, and a report; no Trust Score |

A behavioral Evaluation sends adversarial Probes to your Agent, including prompt injections, jailbreak attempts, and data exfiltration payloads, and measures its responses. You get a quantified Trust Score and specific findings you can fix before deployment. The number of prompts depends on the selected Harnesses and sample size.

### Red Team Evaluations

Red Team uses the registered Agent's context to generate attack seeds, run attackers, judge transcripts, and use reflections to guide later waves. Its report groups vulnerabilities and successful attack strategies. See [Red Team in Diamond](/concepts/platform/diamond#red-team-in-diamond) for the wave loop.

## Behavioral Results: Trust Score

The baseline behavioral Evaluation produces a Trust Score based on three pillars. The Console displays scores on a 0–100 scale; the SDK returns them on a 0.0–1.0 scale:

| Dimension | What It Measures |
|-----------|------------------|
| **Reliability** | Hallucination resistance, consistency, accuracy |
| **Security** | Prompt injection, data leakage, jailbreak resistance |
| **Safety** | Harmful content, policy compliance, ethical behavior |

Higher scores indicate more trustworthy behavior. Use scores to:

- Set deployment gates (e.g., require Trust Score ≥ 70)
- Compare Agent versions
- Track improvements over time
- Identify specific vulnerabilities

## Evaluation Status

Both evaluation types use an `evaluation_id`, but they have different status vocabularies and result endpoints. The SDK treats these as terminal statuses:

| Type | Terminal Statuses | Results to Inspect |
|------|-------------------|--------------------|
| **Behavioral** | `completed`, `succeeded`, `saved`, `failed`, `cancelled` | Evaluation summary and Trust Score when available |
| **Red Team** | `succeeded`, `failed`, `cancelled`, `degraded` | Red Team status; waves, attacks, and report when available |

A `degraded` Red Team run has finished with some attackers lost along the way. Check the findings and failure details before relying on its report.

## Evaluation Options

### Cloud-Hosted Agents

Evaluate a deployed Agent through its registered endpoint. See [Cloud Provider Integrations](/developer-guide/evaluate/cloud-providers) for endpoint requirements and when to add an adapter.

### Local Agents

Use the [local Agent workflow](/developer-guide/evaluate/local-agent) to expose your Agent through an authenticated ngrok tunnel and register its public URL. You can then run a behavioral or Red Team Evaluation against that endpoint. Keep the Agent, proxy, and tunnel running until the Evaluation completes.

## Behavioral Harnesses

| Harness | Description | Use Case |
|---------|-------------|----------|
| `trust_score` | Comprehensive evaluation across all dimensions | Pre-deployment validation |
| `security` | Prompt injection, jailbreaks, data leakage | Security review |
| `reliability` | Hallucination, consistency, accuracy | Quality assurance |
| `safety` | Harmful content, ethics, policy compliance | Safety review |
| `owasp-llm-top-10` | OWASP Top 10 for LLM Applications | Compliance |

Add `_Small` suffix (e.g., `security_Small`) for faster iterations during development.

## Evaluation Workflow

<Steps>
  <Step title="Choose your integration method">
    Use cloud provider integration for deployed agents, or LocalAgentExecutor for local development
  </Step>
  <Step title="Select an Evaluation Type">
    Choose `behavioral` and a Harness for a Trust Score, or `redteam` and optional wave settings for adaptive attacks
  </Step>
  <Step title="Run the Evaluation">
    Execute via the CLI, Python SDK, REST API, or Console
  </Step>
  <Step title="Track Status">
    Use the evaluation ID to follow the status for the selected type until it reaches a terminal state
  </Step>
  <Step title="Analyze Results">
    Review Trust Score and Probe findings for behavioral evaluations, or attack evidence and the report for Red Team evaluations
  </Step>
  <Step title="Remediate Issues">
    Fix vulnerabilities, improve prompts, add Guardrails
  </Step>
  <Step title="Re-evaluate">
    Confirm fixes and track improvement
  </Step>
</Steps>

## Behavioral Sample Size

Use `sample_size` to limit the number of prompts selected per Harness while iterating on behavioral Evaluations. Red Team uses wave, seed, and parallel attacker limits instead.

| Sample Size | Use Case |
|-------------|----------|
| 10–50 Probes | Fast iteration during development |
| 100–500 Probes | Pre-release validation |
| Full Harness | Comprehensive production gate |

Use the `_Small` Harness variants (e.g., `security_Small`) for faster iteration runs that sample a representative subset of Probes.
