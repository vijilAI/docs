---
title: 'Run Evaluations'
description: 'Start and inspect behavioral and Red Team evaluations with the CLI, MCP, REST API, or Python SDK.'
---

Diamond supports two evaluation types. Both run against a registered [Agent](/tutorials/manage-agents) and use an `evaluation_id`, but they accept different settings and produce different evidence.

| Evaluation Type | Inputs | Output |
| --- | --- | --- |
| Behavioral | Standard or custom Harnesses and an optional sample size | Trust Score and Harness results |
| Red Team | Optional wave and attack settings | Attack evidence and a Red Team report |

Red Team does not accept baseline, Harness, sample-size, or local-mode settings.

## Prerequisites

- An authenticated CLI or SDK client, or a bearer token for REST requests. See [SDK Setup](/developer-guide/sdk/setup).
- A registered Agent and its ID or alias.

## Start an Evaluation

<Tabs>
  <Tab title="CLI">

  Run the standard Trust Score Harnesses:

  ```bash
  vijil evaluate "$AGENT_ID" --baseline --sample-size 50
  ```

  Run a Red Team evaluation:

  ```bash
  vijil evaluate "$AGENT_ID" \
    --type redteam \
    --redteam '{"max_waves": 3}'
  ```

  The command waits for a terminal status. Add `--no-wait` to return after creation, or place `--output json` before `evaluate` for JSON output.

  </Tab>
  <Tab title="MCP">

  With the [Vijil MCP server](/developer-guide/agentic/quickstart) configured, ask Claude Code in natural language:

  <Prompt description="Run a safety and security evaluation on agent a1b2c3d4-... with sample size 50, and wait for it to complete">
  Run a safety and security evaluation on agent a1b2c3d4-... with sample size 50, and wait for it to complete
  </Prompt>

  Claude calls `eval_run` with `wait=True` and reports back Trust Scores when the evaluation finishes.

  </Tab>
  <Tab title="SDK">

  `client.evaluate()` creates an evaluation and polls until it reaches a terminal status:

  ```python
  from vijil import Vijil

  client = Vijil()

  behavioral = client.evaluate("<agent-id>", baseline=True, sample_size=50)
  print(behavioral.trust_score)

  redteam = client.evaluate(
      "<agent-id>",
      type="redteam",
      redteam={"max_waves": 3},
  )
  print(redteam.evaluation_id, redteam.status)
  ```

  To start without polling, use the evaluation resource:

  ```python
  behavioral = client.evaluations.create(
      agent_id="<agent-id>",
      baseline=True,
      sample_size=50,
  )
  redteam = client.evaluations.create(
      agent_id="<agent-id>",
      type="redteam",
      redteam={"max_waves": 3},
  )
  ```

  </Tab>
  <Tab title="REST API">

  Create a behavioral evaluation:

  ```bash
  curl -s -X POST "$VIJIL_URL/v1/evaluations/" \
    -H "Authorization: Bearer $TOKEN" \
    -H "Content-Type: application/json" \
    -d "{
      \"agent_id\": \"$AGENT_ID\",
      \"team_id\": \"$TEAM_ID\",
      \"type\": \"behavioral\",
      \"harness_names\": [\"safety\", \"security\"],
      \"sample_size\": 50
    }"
  ```

  Create a Red Team evaluation through the same endpoint:

  ```bash
  curl -s -X POST "$VIJIL_URL/v1/evaluations/" \
    -H "Authorization: Bearer $TOKEN" \
    -H "Content-Type: application/json" \
    -d "{
      \"agent_id\": \"$AGENT_ID\",
      \"team_id\": \"$TEAM_ID\",
      \"type\": \"redteam\",
      \"redteam\": {\"max_waves\": 3}
    }"
  ```

  Both requests return `202 Accepted` with an `evaluation_id` and initial status.

  </Tab>
</Tabs>

## Check Status

Behavioral evaluations can move through `starting`, `pending`, `running`, `completed`, and `saving` before reaching `saved`. They can also end as `succeeded`, `failed`, or `cancelled`.

<CodeGroup>
```bash title="CLI"
vijil evaluations show "$EVALUATION_ID"
```

```python title="SDK"
evaluation = client.evaluations.show("<evaluation-id>")
print(evaluation.status)
```

```bash title="REST"
curl -s "$VIJIL_URL/v1/evaluations/$EVALUATION_ID" \
  -H "Authorization: Bearer $TOKEN"
```
</CodeGroup>

Red Team uses its own progress response and terminal statuses: `succeeded`, `failed`, `cancelled`, or `degraded`.

<CodeGroup>
```bash title="CLI"
vijil evaluations redteam-status "$EVALUATION_ID"
```

```python title="SDK"
status = client.evaluations.redteam_status("<evaluation-id>")
print(status.phase, status.current_wave, status.status)
```

```bash title="REST"
curl -s "$VIJIL_URL/v1/evaluations/$EVALUATION_ID/redteam?team_id=$TEAM_ID" \
  -H "Authorization: Bearer $TOKEN"
```
</CodeGroup>

A `degraded` Red Team evaluation completed with some attacker failures. Inspect its error fields and wave breakdown before using its report.

## Retrieve Results

### Behavioral Results

Behavioral evaluations produce a Trust Score and a hierarchy of Harness, Scenario, and Probe results.

<CodeGroup>
```bash title="CLI"
vijil scores show "$AGENT_ID"
```

```python title="SDK"
score = client.scores.get("<evaluation-id>")
results = client.scores.results("<evaluation-id>")
print(score.trust_score, score.reliability, score.security, score.safety)
```

```bash title="REST"
curl -s "$VIJIL_URL/v1/evaluation-results/$EVALUATION_ID/results?team_id=$TEAM_ID" \
  -H "Authorization: Bearer $TOKEN"
```
</CodeGroup>

Use `client.scores.results()` or the corresponding REST endpoint when you need the complete nested result hierarchy. Use the response listing below when you need filterable, paginated prompt-level evidence.

### Prompt-Level Responses

Retrieve individual prompt and Agent response rows from a completed behavioral evaluation. The method supports both standard and custom Harness evaluations.

<CodeGroup>
```python title="SDK"
page = client.evaluations.responses(
    "<evaluation-id>",
    status="failed",
    limit=50,
    offset=0,
)

for response in page.items:
    print(response.prompt_text)
    print(response.response_text)
    print(response.probe_score)
```

```bash title="REST"
curl -sG "$VIJIL_URL/v1/evaluations/$EVALUATION_ID/responses" \
  -H "Authorization: Bearer $TOKEN" \
  --data-urlencode "team_id=$TEAM_ID" \
  --data-urlencode "status=failed" \
  --data-urlencode "limit=50" \
  --data-urlencode "offset=0"
```
</CodeGroup>

Each row identifies its parent Harness, Scenario, and Probe and includes the prompt, Agent response, parent Probe score, and raw Detector results. A `failed` row belongs to a Probe that scored below the evaluation's pass threshold. Filter by `harness_id`, `scenario_id`, or `probe_id` to narrow the results further.

The CLI does not currently expose this response listing. Red Team evaluations do not support it; use the Red Team evidence methods below instead. See the [`client.evaluations` SDK reference](/developer-guide/sdk/resources#prompt-level-behavioral-responses) for all arguments and the return type.

### Red Team Evidence

Red Team evaluations expose seeds, attacks, judgments, and reflections under the evaluation ID:

<CodeGroup>
```bash title="CLI"
vijil evaluations redteam-seeds "$EVALUATION_ID"
vijil evaluations redteam-attacks "$EVALUATION_ID"
vijil evaluations redteam-judgments "$EVALUATION_ID"
vijil evaluations redteam-reflections "$EVALUATION_ID"
```

```python title="SDK"
seeds = client.evaluations.redteam_seeds("<evaluation-id>")
attacks = client.evaluations.redteam_attacks("<evaluation-id>")
judgments = client.evaluations.redteam_judgments("<evaluation-id>")
reflections = client.evaluations.redteam_reflections("<evaluation-id>")
```

```bash title="REST"
curl -s "$VIJIL_URL/v1/evaluations/$EVALUATION_ID/redteam/attacks?team_id=$TEAM_ID" \
  -H "Authorization: Bearer $TOKEN"
```
</CodeGroup>

Use `--wave` to filter the CLI seed, attack, or judgment commands. The attack and judgment commands also accept `--seed` with `--wave`. See the [Red Team CLI guide](/developer-guide/cli/red-team) for the complete workflow.

## Retrieve Reports

Download the behavioral evaluation PDF:

<CodeGroup>
```bash title="CLI"
vijil reports download "$EVALUATION_ID"
```

```python title="SDK"
pdf_bytes = client.reports.download("<evaluation-id>")
with open("report.pdf", "wb") as report_file:
    report_file.write(pdf_bytes)
```

```bash title="REST"
curl -s "$VIJIL_URL/v1/evaluations/$EVALUATION_ID/pdf?team_id=$TEAM_ID" \
  -H "Authorization: Bearer $TOKEN" \
  -o report.pdf
```
</CodeGroup>

Retrieve the Red Team report as structured JSON, Markdown, or PDF:

<CodeGroup>
```bash title="CLI"
vijil evaluations redteam-report "$EVALUATION_ID" --format md
```

```python title="SDK"
report = client.evaluations.redteam_report("<evaluation-id>")
markdown = client.evaluations.redteam_report_markdown("<evaluation-id>")
pdf_bytes = client.evaluations.redteam_report_pdf("<evaluation-id>")
```

```bash title="REST"
curl -s "$VIJIL_URL/v1/evaluations/$EVALUATION_ID/redteam/report?team_id=$TEAM_ID" \
  -H "Authorization: Bearer $TOKEN"
```
</CodeGroup>

## List and Manage Evaluations

<CodeGroup>
```bash title="CLI"
vijil evaluations list --agent "$AGENT_ID"
```

```python title="SDK"
page = client.evaluations.list(agent_id="<agent-id>")
for evaluation in page.items:
    print(evaluation.id, evaluation.status)

client.evaluations.delete("<evaluation-id>")
```

```bash title="REST"
curl -s "$VIJIL_URL/v1/evaluations/" \
  -H "Authorization: Bearer $TOKEN"

curl -s -X POST "$VIJIL_URL/v1/evaluations/$EVALUATION_ID/cancel" \
  -H "Authorization: Bearer $TOKEN"

curl -s -X DELETE "$VIJIL_URL/v1/evaluations/$EVALUATION_ID" \
  -H "Authorization: Bearer $TOKEN"
```
</CodeGroup>

The current CLI supports listing and showing evaluations. Use the SDK or REST API when you need to delete an evaluation, and use REST to cancel one.
