This page is the full command reference. For what Red Team does and which interfaces reach it, start with the [Red Team Overview](/developer-guide/red-team/overview).

Red Team goes beyond standard [Harnesses](/concepts/evaluation-components/harness) by simulating realistic adversarial users. [Personas](/owner-guide/simulate-environment/personas) define who is attacking, [Policies](/owner-guide/simulate-environment/policies) define the rules [Agents](/owner-guide/register-agents/what-is-an-agent) must follow, and Engagements execute multi-strategy attack sequences over several waves.

Each Red Team run and its results share one `evaluation_id`. Use `vijil evaluate` to start the evaluation, then use `vijil evaluations redteam-*` to inspect it.

## Start a Red Team Evaluation

Run a Red Team evaluation and wait for a terminal status:

```bash
vijil evaluate "$AGENT_ID" --type redteam
```

The command prints progress while the evaluation runs. Its terminal statuses are `succeeded`, `failed`, `cancelled`, and `degraded`. A `degraded` evaluation finished with some attacker failures; inspect its status details before using the report.

Add `--no-wait` to return immediately after creation. Save the evaluation ID from the output for later commands:

```bash
vijil evaluate "$AGENT_ID" --type redteam --no-wait
export EVALUATION_ID="<evaluation-id>"
```

### Configure the Evaluation

Pass a JSON object through `--redteam` to override the default wave settings:

```bash
vijil evaluate "$AGENT_ID" \
  --type redteam \
  --redteam '{"max_waves": 3, "max_seeds_per_wave": 5}'
```

The configuration accepts these fields:

| Field | Description |
| --- | --- |
| `min_waves` | Lower bound for adaptive waves |
| `max_waves` | Upper bound for adaptive waves |
| `max_seeds_per_wave` | Seed limit for each wave |
| `max_parallel_attackers` | Concurrent attacker limit |
| `attack_execution` | Attack timeout settings |
| `taxonomy_file` | Risk taxonomy file |
| `advanced` | Attempts, retries, strategies, turns, and text gradient settings |

Red Team runs directly against the registered Agent. It does not accept `--baseline`, `--bespoke`, `--sample-size`, `--local`, or `--harness-name`.

## Inspect Progress and Evidence

| Command | Description |
| --- | --- |
| `vijil evaluations redteam-status <evaluation-id>` | Show run and wave progress |
| `vijil evaluations redteam-seeds <evaluation-id>` | List generated attack seeds |
| `vijil evaluations redteam-attacks <evaluation-id>` | List attacks or return one attack |
| `vijil evaluations redteam-judgments <evaluation-id>` | List judgments or return one judgment |
| `vijil evaluations redteam-reflections <evaluation-id>` | List reflections or return one wave's reflection |
| `vijil evaluations redteam-report <evaluation-id>` | Retrieve the final report |

Each command accepts `--team <team-id>`. If you omit it, the CLI uses the default team from your configuration.

### Status

Show the evaluation's status, current phase, wave progress, attacker counts, errors, and degradation details:

```bash
vijil evaluations redteam-status "$EVALUATION_ID"
```

Use the global output option before the command when you need JSON:

```bash
vijil --output json evaluations redteam-status "$EVALUATION_ID"
```

### Seeds

Seeds describe the risks and instructions that attackers explore. List every seed or filter by wave:

```bash
vijil evaluations redteam-seeds "$EVALUATION_ID"
vijil evaluations redteam-seeds "$EVALUATION_ID" --wave "$WAVE_ID"
```

### Attacks

Attack results include the attacker type, execution status, transcript, and error details. List results by evaluation or wave:

```bash
vijil evaluations redteam-attacks "$EVALUATION_ID"
vijil evaluations redteam-attacks "$EVALUATION_ID" --wave "$WAVE_ID"
```

Return one attack by combining `--wave` and `--seed`:

```bash
vijil evaluations redteam-attacks "$EVALUATION_ID" \
  --wave "$WAVE_ID" \
  --seed "$SEED_ID"
```

### Judgments

Judgments record whether an attack succeeded, whether it could cause harm, and whether the response leaked artifacts:

```bash
vijil evaluations redteam-judgments "$EVALUATION_ID"
vijil evaluations redteam-judgments "$EVALUATION_ID" --wave "$WAVE_ID"
```

Return one judgment by combining `--wave` and `--seed`:

```bash
vijil evaluations redteam-judgments "$EVALUATION_ID" \
  --wave "$WAVE_ID" \
  --seed "$SEED_ID"
```

### Reflections

After each completed wave, the evaluation summarizes successful seeds, saturated outcomes, and new strategy patterns. List all reflections or select one wave:

```bash
vijil evaluations redteam-reflections "$EVALUATION_ID"
vijil evaluations redteam-reflections "$EVALUATION_ID" --wave "$WAVE_ID"
```

## Retrieve the Report

The final report summarizes vulnerabilities, policy violations, leaked artifacts, and successful strategies. JSON is the default format:

```bash
vijil evaluations redteam-report "$EVALUATION_ID"
```

Choose Markdown or PDF with `--format`. Use `--output` to write the report to a file; PDF output requires it:

```bash
vijil evaluations redteam-report "$EVALUATION_ID" \
  --format md \
  --output red-team-report.md

vijil evaluations redteam-report "$EVALUATION_ID" \
  --format pdf \
  --output red-team-report.pdf
```

Add `--force-regenerate` to rebuild a cached PDF:

```bash
vijil evaluations redteam-report "$EVALUATION_ID" \
  --format pdf \
  --output red-team-report.pdf \
  --force-regenerate
```

<Note>
For the shared behavioral and Red Team startup options, see the [CLI evaluation guide](/developer-guide/cli/evaluate).
</Note>
  
## Red Team Engagements

A Red Team Engagement runs adversarial attacks against your Agent in waves, learning from each wave to plan the next. See [Engagements](/concepts/red-team/engagements) for how the loop works.

| Command | Description |
|---------|-------------|
| `vijil redteam create` | Create an Engagement |
| `vijil redteam list` | List Engagements |
| `vijil redteam status` | Get Engagement status |
| `vijil redteam results` | Get Engagement results |
| `vijil redteam cancel` | Cancel a running Engagement |
| `vijil redteam delete` | Delete an Engagement |
| `vijil redteam seeds` | List attack seeds |
| `vijil redteam attacks` | List attacker runs |
| `vijil redteam attack` | Get one attacker run |
| `vijil redteam judgments` | List judgments |
| `vijil redteam judgment` | Get one judgment |
| `vijil redteam reflections` | List reflections |
| `vijil redteam reflection` | Get one wave's reflection |
| `vijil redteam report` | Get the final report |
| `vijil redteam report-md` | Get the final report as Markdown |

### `vijil redteam create`

Create and start an Engagement. Only `--agent-id` is required, because the service fetches the target endpoint and Agent card from the Agent registry.

```bash
vijil redteam create \
  --agent-id "$AGENT_ID" \
  --policy-ids '["<policy_id>"]' \
  --persona-ids '["<persona_id>"]' \
  --redteam '{"max_waves": 3, "max_seeds_per_wave": 5}' \
  --wait
```

| Flag | Description | Required |
|------|-------------|----------|
| `--agent-id` | Agent to attack. The service resolves its endpoint and Agent card. | Yes |
| `--persona-ids` | [Persona](/owner-guide/simulate-environment/personas) IDs to use (JSON array) | |
| `--policy-ids` | [Policy](/owner-guide/simulate-environment/policies) IDs the judge tests against (JSON array) | |
| `--redteam` | Wave and seed overrides (JSON object) | |
| `--advanced` | Attacker behavior overrides (JSON object) | |
| `--wait` | Poll until the Engagement completes | |
| `--json` | Output as JSON | |

Save the Engagement ID from the output:

```bash
export ENGAGEMENT_ID="e1d2c3b4-..."
```

<Note>
`--redteam` controls the shape of the run, such as `min_waves`, `max_waves`, `max_seeds_per_wave`, and `max_parallel_attackers`. `--advanced` controls how hard each attacker works before giving up. Both map onto the Console sliders described in [Run a Red Team Campaign](/owner-guide/red-team/running-campaigns). The exact JSON keys come from the `vijil-redteam` schemas package, so check `vijil redteam create --help` for the set your deployment accepts.
</Note>

### `vijil redteam list`

List Engagements for the active team, showing `engagement_id`, `status`, `phase`, and `created_at`.

```bash
vijil redteam list
```

### `vijil redteam status`

Get one Engagement's live state, including phase, current wave, attackers completed, and attackers errored.

```bash
vijil redteam status <engagement_id> --json
```

### `vijil redteam results`

Get the aggregated results for an Engagement.

```bash
vijil redteam results <engagement_id> --json
```

### `vijil redteam cancel`

Cancel a running Engagement.

```bash
vijil redteam cancel <engagement_id>
```

### `vijil redteam delete`

Delete an Engagement.

```bash
vijil redteam delete <engagement_id>
vijil redteam delete <engagement_id> --yes   # skip confirmation
```

### `vijil redteam seeds`

List the attack seeds generated for an Engagement, showing `wave_id`, `seed_id`, `instruction`, and `risk_type`.

```bash
vijil redteam seeds <engagement_id>
vijil redteam seeds <engagement_id> --wave-id 1
```

### `vijil redteam attacks`

List attacker runs, showing `wave_id`, `seed_id`, `attacker_type`, and `status`.

```bash
vijil redteam attacks <engagement_id> --wave-id 1
```

### `vijil redteam attack`

Get one attacker run, including its strategy and transcript.

```bash
vijil redteam attack <engagement_id> <wave_id> <seed_id> --json
```

### `vijil redteam judgments`

List judgments, showing `wave_id`, `seed_id`, `is_success`, and `potential_harm`.

```bash
vijil redteam judgments <engagement_id> --wave-id 1
```

### `vijil redteam judgment`

Get one judgment in full.

```bash
vijil redteam judgment <engagement_id> <wave_id> <seed_id> --json
```

### `vijil redteam reflections`

List every wave's reflection, which is the Engagement's own account of what worked.

```bash
vijil redteam reflections <engagement_id>
```

### `vijil redteam reflection`

Get one wave's reflection.

```bash
vijil redteam reflection <engagement_id> <wave_id> --json
```

### `vijil redteam report`

Get the final report, with clustered vulnerabilities, policy violations, leaked artifacts, and successful strategies.

```bash
vijil redteam report <engagement_id> --json
```

### `vijil redteam report-md`

Get the final report rendered as Markdown, which is convenient for pasting into tickets.

```bash
vijil redteam report-md <engagement_id>
```
