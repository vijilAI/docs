This page is the full command reference. For what Red Team does and which interfaces reach it, start with the [Red Team Overview](/developer-guide/red-team/overview).

Red Team goes beyond standard [Harnesses](/concepts/evaluation-components/harness) by simulating realistic adversarial users. [Personas](/owner-guide/simulate-environment/personas) define who is attacking, [Policies](/owner-guide/simulate-environment/policies) define the rules [Agents](/owner-guide/register-agents/what-is-an-agent) must follow, and Engagements execute multi-strategy attack sequences over several waves.

## Personas

Personas represent user archetypes — from benign customers to malicious attackers — that shape how [Probes](/concepts/evaluation-components/probe) are generated for [custom Harnesses](/developer-guide/evaluate/custom-harnesses).

| Command | Description |
|---------|-------------|
| `vijil persona preset-list` | List built-in Persona presets |
| `vijil persona from-preset` | Create a Persona from a preset |
| `vijil persona create` | Create a custom Persona |
| `vijil persona list` | List Personas |
| `vijil persona get` | Get a specific Persona |
| `vijil persona update` | Update a Persona |
| `vijil persona delete` | Delete a Persona |

### `vijil persona preset-list`

List built-in Persona presets. Presets are categorized as `professional`, `adversarial`, or `support`.

```bash
vijil persona preset-list
vijil persona preset-list --preset-category adversarial
```

| Flag | Description |
|------|-------------|
| `--preset-category` | Filter by category: `professional`, `adversarial`, `support` |
| `--limit` | Maximum number of results |
| `--offset` | Number of results to skip |
| `--json` | Output as JSON |

### `vijil persona from-preset`

Create a Persona from a preset.

```bash
vijil persona from-preset <preset_id>
vijil persona from-preset <preset_id> --name-override "Custom Attacker"
```

| Flag | Description |
|------|-------------|
| `--name-override` | Override the preset's default name |
| `--json` | Output as JSON |

### `vijil persona create`

Create a custom Persona.

```bash
vijil persona create \
  --name "Frustrated Customer" \
  --role "End user" \
  --intent adversarial \
  --knowledge-level intermediate
```

| Flag | Description |
|------|-------------|
| `--name` | Persona display name (required) |
| `--role` | Persona role (required) |
| `--role-description` | Extended role description |
| `--intent` | `benign`, `curious`, `adversarial`, or `malicious` |
| `--knowledge-level` | `beginner`, `intermediate`, `advanced`, or `expert` |
| `--skill-level` | `novice`, `competent`, `proficient`, or `expert` |
| `--language` | Language the Persona uses |
| `--tags` | Tags (JSON array) |
| `--json` | Output as JSON |

### `vijil persona list`

List Personas for the active team.

```bash
vijil persona list
vijil persona list --intents adversarial,malicious
```

| Flag | Description |
|------|-------------|
| `--intents` | Filter by intent(s): `benign`, `curious`, `adversarial`, `malicious` |
| `--is-preset` | Show only presets |
| `--search` | Search in name, description, and role |
| `--limit` | Maximum number of results |
| `--offset` | Number of results to skip |
| `--json` | Output as JSON |

### `vijil persona get`

Get a specific Persona.

```bash
vijil persona get <persona_id> --json
```

### `vijil persona update`

Update a Persona.

```bash
vijil persona update <persona_id> --intent malicious --skill-level expert
```

Accepts the same flags as `vijil persona create`.

### `vijil persona delete`

Delete a Persona.

```bash
vijil persona delete <persona_id>
vijil persona delete <persona_id> --yes   # skip confirmation
```

## Policies

Policies define the rules and constraints agents must follow. Attaching Policies to a [custom Harness](/developer-guide/evaluate/custom-harnesses) generates Probes that specifically test compliance.

| Command | Description |
|---------|-------------|
| `vijil policy preset-list` | List built-in Policy presets |
| `vijil policy from-preset` | Create a Policy from a preset |
| `vijil policy create` | Create a custom Policy |
| `vijil policy list` | List Policies |
| `vijil policy get` | Get a specific Policy |
| `vijil policy activate` | Activate a Policy |
| `vijil policy patch` | Update a Policy |
| `vijil policy delete` | Delete a Policy |
| `vijil policy add-rule` | Add a rule to a Policy |
| `vijil policy rule-list` | List rules in a Policy |

### `vijil policy preset-list`

List built-in Policy presets.

```bash
vijil policy preset-list
vijil policy preset-list --category compliance
```

| Flag | Description |
|------|-------------|
| `--category` | Filter by category |
| `--limit` | Maximum number of results |
| `--offset` | Number of results to skip |
| `--json` | Output as JSON |

### `vijil policy from-preset`

Copy a preset Policy into your team.

```bash
vijil policy from-preset <preset_id>
vijil policy from-preset <preset_id> --name-override "GDPR Policy"
```

### `vijil policy create`

Create a Policy from text.

```bash
vijil policy create \
  --name "Data Handling Policy" \
  --category privacy \
  --source-text "The agent must not store or repeat personal data..."
```

| Flag | Description | Required |
|------|-------------|----------|
| `--name` | Policy display name | Yes |
| `--category` | `privacy`, `ethics`, `security`, `compliance`, `operational`, `brand`, or `custom` | Yes |
| `--description` | Policy description | |
| `--source-text` | Full policy text | |
| `--tags` | Tags (JSON array) | |
| `--json` | Output as JSON | |

### `vijil policy list`

List Policies for the active team.

```bash
vijil policy list
vijil policy list --category security --status active
```

| Flag | Description |
|------|-------------|
| `--category` | Filter by category |
| `--status` | Filter by status |
| `--search` | Search in name and description |
| `--limit` | Maximum number of results |
| `--offset` | Number of results to skip |
| `--json` | Output as JSON |

### `vijil policy get`

Get a specific Policy.

```bash
vijil policy get <policy_id> --json
```

### `vijil policy activate`

Activate a draft Policy so it can be used in Harness generation.

```bash
vijil policy activate <policy_id>
```

### `vijil policy patch`

Update Policy metadata.

```bash
vijil policy patch <policy_id> \
  --name "Updated Policy Name" \
  --status active
```

| Flag | Description |
|------|-------------|
| `--name` | New name |
| `--description` | New description |
| `--category` | New category |
| `--status` | `draft`, `active`, or `archived` |
| `--source-text` | New policy text |
| `--tags` | Tags (JSON array) |
| `--json` | Output as JSON |

### `vijil policy delete`

Delete a Policy.

```bash
vijil policy delete <policy_id>
vijil policy delete <policy_id> --yes
```

### `vijil policy add-rule`

Add a structured rule to a Policy.

```bash
vijil policy add-rule <policy_id> \
  --rule-type prohibition \
  --action "share" \
  --natural-language "The agent must not share customer PII with third parties." \
  --consequence '{}'
```

| Flag | Description | Required |
|------|-------------|----------|
| `--rule-type` | `permission`, `prohibition`, `obligation`, or `recommendation` | Yes |
| `--action` | Action the rule governs | Yes |
| `--natural-language` | Human-readable rule statement | Yes |
| `--consequence` | Consequence definition (JSON object) | Yes |
| `--target` | Target entity | |
| `--assignee` | Assignee entity | |
| `--category` | Rule category | |
| `--json` | Output as JSON | |

### `vijil policy rule-list`

List rules within a Policy.

```bash
vijil policy rule-list --policy-id <policy_id>
```

| Flag | Description |
|------|-------------|
| `--policy-id` | Filter by policy ID |
| `--status` | Filter by rule status |
| `--category` | Filter by category |
| `--limit` | Maximum number of results |
| `--offset` | Number of results to skip |
| `--json` | Output as JSON |

## Red Team Engagements

A Red Team Engagement runs adversarial attacks against your Agent in waves, learning from each wave to plan the next. See [Engagements](/concepts/red-team/engagements) for how the loop works.

| Command | Description |
|---------|-------------|
| `vijil xteaming create` | Create an Engagement |
| `vijil xteaming list` | List Engagements |
| `vijil xteaming status` | Get Engagement status |
| `vijil xteaming results` | Get Engagement results |
| `vijil xteaming cancel` | Cancel a running Engagement |
| `vijil xteaming delete` | Delete an Engagement |
| `vijil xteaming seeds` | List attack seeds |
| `vijil xteaming attacks` | List attacker runs |
| `vijil xteaming attack` | Get one attacker run |
| `vijil xteaming judgments` | List judgments |
| `vijil xteaming judgment` | Get one judgment |
| `vijil xteaming reflections` | List reflections |
| `vijil xteaming reflection` | Get one wave's reflection |
| `vijil xteaming report` | Get the final report |
| `vijil xteaming report-md` | Get the final report as Markdown |

### `vijil xteaming create`

Create and start an Engagement. Only `--agent-id` is required, because the service fetches the target endpoint and Agent card from the Agent registry.

```bash
vijil xteaming create \
  --agent-id "$AGENT_ID" \
  --policy-ids '["<policy_id>"]' \
  --persona-ids '["<persona_id>"]' \
  --redteam '{"max_waves": 3, "max_seeds_per_wave": 5}' \
  --wait
```

| Flag | Description | Required |
|------|-------------|----------|
| `--agent-id` | Agent to attack. The service resolves its endpoint and Agent card. | Yes |
| `--persona-ids` | [Persona](/owner-guide/simulate-environment/personas) IDs to use (JSON array) | |
| `--policy-ids` | [Policy](/owner-guide/simulate-environment/policies) IDs the judge tests against (JSON array) | |
| `--redteam` | Wave and seed overrides (JSON object) | |
| `--xteaming` | Attacker behavior overrides (JSON object) | |
| `--wait` | Poll until the Engagement completes | |
| `--json` | Output as JSON | |

Save the Engagement ID from the output:

```bash
export ENGAGEMENT_ID="e1d2c3b4-..."
```

<Note>
`--redteam` controls the shape of the run, such as `min_waves`, `max_waves`, `max_seeds_per_wave`, and `max_parallel_attackers`. `--xteaming` controls how hard each attacker works before giving up. Both map onto the Console sliders described in [Run a Red Team Campaign](/owner-guide/red-team/running-campaigns). The exact JSON keys come from the `vijil-redteam` schemas package, so check `vijil xteaming create --help` for the set your deployment accepts.
</Note>

### `vijil xteaming list`

List Engagements for the active team, showing `engagement_id`, `status`, `phase`, and `created_at`.

```bash
vijil xteaming list
```

### `vijil xteaming status`

Get one Engagement's live state, including phase, current wave, attackers completed, and attackers errored.

```bash
vijil xteaming status <engagement_id> --json
```

### `vijil xteaming results`

Get the aggregated results for an Engagement.

```bash
vijil xteaming results <engagement_id> --json
```

### `vijil xteaming cancel`

Cancel a running Engagement.

```bash
vijil xteaming cancel <engagement_id>
```

### `vijil xteaming delete`

Delete an Engagement.

```bash
vijil xteaming delete <engagement_id>
vijil xteaming delete <engagement_id> --yes   # skip confirmation
```

### `vijil xteaming seeds`

List the attack seeds generated for an Engagement, showing `wave_id`, `seed_id`, `instruction`, and `risk_type`.

```bash
vijil xteaming seeds <engagement_id>
vijil xteaming seeds <engagement_id> --wave-id 1
```

### `vijil xteaming attacks`

List attacker runs, showing `wave_id`, `seed_id`, `attacker_type`, and `status`.

```bash
vijil xteaming attacks <engagement_id> --wave-id 1
```

### `vijil xteaming attack`

Get one attacker run, including its strategy and transcript.

```bash
vijil xteaming attack <engagement_id> <wave_id> <seed_id> --json
```

### `vijil xteaming judgments`

List judgments, showing `wave_id`, `seed_id`, `is_success`, and `potential_harm`.

```bash
vijil xteaming judgments <engagement_id> --wave-id 1
```

### `vijil xteaming judgment`

Get one judgment in full.

```bash
vijil xteaming judgment <engagement_id> <wave_id> <seed_id> --json
```

### `vijil xteaming reflections`

List every wave's reflection, which is the Engagement's own account of what worked.

```bash
vijil xteaming reflections <engagement_id>
```

### `vijil xteaming reflection`

Get one wave's reflection.

```bash
vijil xteaming reflection <engagement_id> <wave_id> --json
```

### `vijil xteaming report`

Get the final report, with clustered vulnerabilities, policy violations, leaked artifacts, and successful strategies.

```bash
vijil xteaming report <engagement_id> --json
```

### `vijil xteaming report-md`

Get the final report rendered as Markdown, which is convenient for pasting into tickets.

```bash
vijil xteaming report-md <engagement_id>
```
