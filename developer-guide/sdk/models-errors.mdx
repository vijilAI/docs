The SDK uses typed Pydantic models for structured platform records. Depending on the operation, it can also return a `Page[T]`, dictionary, list, byte string, or `None`.

Hand-curated models inherit from `VijilModel`, which ignores unknown response fields. Models generated from the Console schemas inherit directly from Pydantic's `BaseModel`. When `vijil.models` exports a model, import it there. Treat `vijil._generated` as internal implementation detail.

## Pagination

### `Page[T]`

Most paginated `list()` methods return `Page[T]`. A page supports iteration and `len()`.

```python
page = client.agents.list()

for agent in page:
    print(agent.id, agent.agent_name)

print(page.items)      # list[Agent]
print(page.total)      # total matching records
print(page.has_more)   # whether len(page.items) is less than page.total
```

`Page[T]` normalizes the Console's `items` or `results` collections and its `total` or `count` fields. Some methods intentionally return a plain list, such as `client.rca_runs.list()`.

## Core Models

### `Evaluation`

`Evaluation` normalizes both live Evaluation records and persisted summaries. The `evaluation_id` response field maps to the model's `id`, and `overall_score` maps to `trust_score`.

```python
evaluation.id             # str
evaluation.agent_id       # str | None
evaluation.status         # str
evaluation.harness_names  # list[str]
evaluation.trust_score    # float | None
evaluation.scores         # dict[str, float] | None
evaluation.dimensions     # Dimensions | None
evaluation.created_at     # int | str | None
evaluation.completed_at   # int | str | None
evaluation.error_message  # str | None
```

### `Dimensions`

```python
dimensions.reliability  # float | None
dimensions.security     # float | None
dimensions.safety       # float | None
```

The SDK builds `dimensions` from the Console's pillar score fields or its `scores` dictionary.

### `EvaluationResponse`

`client.evaluations.responses()` returns a `Page[EvaluationResponse]` containing individual behavioral Evaluation records.

```python
response.harness_id       # str
response.scenario_id      # str
response.probe_id         # str
response.probe_score      # float
response.prompt_id        # str
response.prompt_text      # str | None
response.response_text    # str
response.status           # "passed" | "failed"
response.detector_results # dict[str, Any]
```

### `Agent`

The Console schema uses `agent_name` and `agent_url` as the public field names.

```python
agent.id                 # str
agent.agent_name         # str
agent.model_name         # str
agent.agent_url          # str | None
agent.team_id            # str
agent.status             # str | None
agent.access_level       # str | None
agent.protocol           # str | None
agent.deployment         # str | None
agent.latest_evaluation  # AgentLatestEvaluation | None
```

The `client.agents` resource removes API key values from Console responses before returning an `Agent`.

### `Job`

```python
job.id          # str
job.agent_id    # str | None
job.status      # str
job.mode        # str | None
job.created_at  # int | str | None
job.error       # str | None
```

Lifecycle methods return the terminal `Job` record even when its status is `failed` or `cancelled`. Inspect `job.status` and `job.error` after polling.

### `TrustScore`

```python
score.evaluation_id  # str | None
score.agent_id       # str | None
score.trust_score    # float | None
score.reliability    # float | None
score.security       # float | None
score.safety         # float | None
score.pillar_details # dict[str, PillarDetail]
score.harness_names  # list[str]
score.status         # str | None
score.evaluated_at   # int | str | None
```

Use `score.summarize(results=results, scale=100)` to flatten full Evaluation results into summary, Harness, Scenario, and Probe rows. Get `results` with [`client.scores.results()`](/developer-guide/sdk/resources#client-scores).

### `DomeConfig`

```python
dome.id             # str | None
dome.agent_id       # str | None
dome.guards         # list[str]
dome.mode           # str
dome.input_guards   # list[str]
dome.output_guards  # list[str]
```

### `Harness` and `Report`

| Model | Key Fields | Produced By |
|-------|------------|-------------|
| `Harness` | `id`, `name`, `type`, `agent_id`, `persona_ids`, `policy_ids`, `status`, `prompt_count` | `client.harnesses.*` |
| `Report` | `id`, `agent_id`, `status`, `format`, `created_at` | `client.reports.*` |

`Report.created_at` can be a Unix timestamp or an ISO-formatted string.

## Errors

Import SDK exceptions from `vijil.exceptions`:

```python
from vijil.exceptions import (
    ConsoleRejected,
    ContractDrift,
    NetworkError,
    SDKValidationFailed,
    VijilAuthError,
    VijilConfigError,
    VijilError,
    VijilJobFailedError,
    VijilNotFoundError,
    VijilRateLimitError,
    VijilServerError,
    VijilValidationError,
)
```

All concrete SDK exceptions inherit from `VijilError`. The hierarchy supports two ways to classify a failure:

```text
VijilError
├── ConsoleRejected
│   ├── VijilAuthError
│   ├── VijilNotFoundError
│   ├── VijilValidationError
│   ├── VijilRateLimitError
│   └── VijilServerError
├── SDKValidationFailed
├── NetworkError
├── ContractDrift
├── VijilJobFailedError
└── VijilConfigError
```

### Source-Attributed Errors

Each concrete exception exposes a `source` and a `remediation` hint.

| Exception | Source | Meaning | Specific Attributes |
|-----------|--------|---------|---------------------|
| `ConsoleRejected` | `"console"` | Console returned a non-success HTTP response | `reason`, `status_code` |
| `SDKValidationFailed` | `"sdk"` | The SDK rejected invalid arguments before sending a request | `field`, `expected`, `actual` |
| `NetworkError` | `"network"` | No HTTP response arrived because of a transport failure | `transport_error` |
| `ContractDrift` | `"drift"` | A successful response did not match the model expected by the SDK | `expected_shape`, `actual_shape` |

Catch `ConsoleRejected` to handle every Console rejection together, or catch one of its status-specific subclasses.

### HTTP Status Errors

| Exception | HTTP Status | Specific Attributes |
|-----------|-------------|---------------------|
| `VijilAuthError` | `401`, `403` | `status_code` |
| `VijilNotFoundError` | `404` | `resource_type`, `resource_id` when available |
| `VijilValidationError` | `400`, `422` | `details` |
| `VijilRateLimitError` | `429` | `retry_after` |
| `VijilServerError` | `5xx` | `status_code` |

Other non-success statuses, such as `409`, raise `ConsoleRejected` directly.

<Tip>
`SDKValidationFailed` and `VijilValidationError` represent different failure locations. The first means local SDK validation stopped the request. The second means the Console rejected a request with HTTP `400` or `422`.
</Tip>

### Configuration and Job Errors

| Exception | When |
|-----------|------|
| `VijilConfigError` | The SDK cannot load or decode required local configuration or state |
| `VijilJobFailedError` | Exception type defined for asynchronous job failures; current lifecycle methods return failed terminal models instead of raising it |

### Error-Handling Pattern

Catch the narrowest actionable exception before its parent class.

```python
from vijil.exceptions import (
    ConsoleRejected,
    ContractDrift,
    NetworkError,
    SDKValidationFailed,
    VijilError,
    VijilNotFoundError,
)

try:
    evaluation = client.evaluate("agent-id", baseline=True)
except SDKValidationFailed as error:
    print(f"Invalid {error.field}: expected {error.expected}")
except VijilNotFoundError as error:
    print(f"Resource not found: {error.resource_id or error}")
except ConsoleRejected as error:
    print(f"Console rejected the request ({error.status_code}): {error.reason}")
except NetworkError as error:
    print(f"Network failure: {error.transport_error}")
except ContractDrift as error:
    print(f"Unexpected response shape: {error.actual_shape}")
except VijilError as error:
    print(f"Vijil SDK failure: {error}")
else:
    print(evaluation.trust_score)
```

## Automatic Retries

The HTTP client makes at most three total attempts for a request:

- For transport failures and `5xx` responses, it waits one second before the second attempt and two seconds before the third.
- For `429` responses, it uses a numeric `Retry-After` value. If the header is missing or invalid, it waits one second.
- For a `401` response, it performs one refresh-and-retry when the credentials support token refresh.

After the final attempt, the SDK raises `NetworkError`, `VijilRateLimitError`, or `VijilServerError`, depending on the last failure. Individual operations can disable retries when repeating the request would be unsafe. Multipart uploads do not retry automatically.
