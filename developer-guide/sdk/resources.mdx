title: "Resources"
description: "Use low-level Vijil SDK resource accessors for individual platform operations."
---

Resource accessors are attributes on the `Vijil` client. While [lifecycle methods](/developer-guide/sdk/lifecycle-methods) coordinate complete workflows, resources let you start an operation without waiting, retrieve individual records, or use operations that do not have a lifecycle shortcut.

Standard `list()` methods return a [`Page[T]`](/developer-guide/sdk/models-errors/#paget); iterate `page.items` for the results. Red Team artifact methods return their own typed responses.

| Accessor | Methods |
|----------|---------|
| `client.agents` | `list`, `show`, `create`, `update`, `delete` |
| `client.evaluations` | `list`, `show`, `create`, `poll_status`, `responses`, `delete`, and Red Team reads below |
| `client.harnesses` | `list`, `show`, `create`, `delete` |
| `client.scores` | `show`, `history` |
| `client.reports` | `list`, `show`, `download` |
| `client.dome` | `list`, `show`, `default`, `update` |
| `client.jobs` | `list`, `show`, `status`, `create`, `cancel` |
| `client.genomes` | `list`, `show`, `versions`, `history`, `diff` |
| `client.proposals` | `list`, `show`, `approve`, `apply`, `reject` |
| `client.policies` | `list`, `show`, `create`, `update`, `delete` |
| `client.personas` | `list`, `show`, `create`, `update`, `delete` |
| `client.monitor` | `traces`, `logs` |
| `client.agent_tunnel` | `get`, `revoke` |
| `client.rca_runs` | `create`, `list`, `show`, `tickets` |

## `client.agents`

Manage [Agent](/owner-guide/register-agents/what-is-an-agent) configurations.

```python
page = client.agents.list(team_id="optional-team-id")
agent = client.agents.show("agent-id")
agent = client.agents.create(
    name="My Agent",
    url="https://agent.example.com/v1",
)
agent = client.agents.update("agent-id", name="New Name")
archived_agent = client.agents.archive("agent-id")
```

`archive()` performs a soft deletion and returns the archived `Agent`. The older `delete()` method calls `archive()` for backward compatibility but returns `None`; prefer `archive()` in new code.

## `client.evaluations`

Manage both [Evaluation types](/developer-guide/evaluate/overview). Use [`client.evaluate()`](/developer-guide/sdk/lifecycle-methods#client-evaluate) for the polling workflow; `create()` starts an evaluation without waiting.

```python
page = client.evaluations.list(agent_id="optional-agent-id")
evaluation = client.evaluations.show("evaluation-id")
behavioral = client.evaluations.create(agent_id="agent-id", baseline=True)
redteam = client.evaluations.create(
    agent_id="agent-id",
    type="redteam",
    redteam={"max_waves": 2},
)
evaluation_id = redteam.id
status = client.evaluations.redteam_status(evaluation_id)
```

Red Team creation returns an `Evaluation` with an ID. Use that `evaluation_id` for all Red Team status, artifact, and report reads. `poll_status()` is for behavioral evaluations; use `redteam_status()` for Red Team. Red Team does not accept `baseline`, Harness, or `sample_size` settings.

### Prompt-Level Behavioral Responses

Use `responses()` to retrieve flattened prompt and response rows from a completed behavioral evaluation, including an evaluation that uses a custom Harness. Each item identifies its parent Harness, Scenario, and Probe and includes the Agent response and raw Detector results.

```python
page = client.evaluations.responses(
    "evaluation-id",
    status="failed",
    limit=50,
    offset=0,
)

for response in page.items:
    print(response.prompt_text)
    print(response.response_text)
    print(response.probe_score)
    print(response.detector_results)
```

The method returns a [`Page[EvaluationResponse]`](/developer-guide/sdk/models-errors#evaluationresponse). `page.total` is the number of rows that match the filters before pagination.

| Argument | Description |
|----------|-------------|
| `evaluation_id` | Required evaluation UUID |
| `team_id` | Team UUID; defaults to the team configured on the client |
| `harness_id` | Include rows from one Harness |
| `scenario_id` | Include rows from one Scenario |
| `probe_id` | Include rows from one Probe |
| `status` | Include `passed` or `failed` Probe results; omit it to include all results |
| `limit` | Rows to return, from 1 to 500; defaults to 50 |
| `offset` | Matching rows to skip; defaults to 0 |

`failed` means that the parent Probe scored below the evaluation's pass threshold. It does not describe an individual Detector result. Call `responses()` after the Console saves the evaluation results. The method is not available for Red Team evaluations; use the Red Team artifact methods instead.

### Red Team Status, Artifacts, and Reports

All methods below take an `evaluation_id` and an optional `team_id`.

| Method | Other Arguments | Returns |
|--------|----------------------|---------|
| `redteam_status` | — | `RedteamStatusResponse` with run and wave progress |
| `redteam_seeds` | Optional `wave_id` filter | `SeedListResponse` |
| `redteam_attacks` | Optional `wave_id` filter | `AttackListResponse` |
| `redteam_attack` | `wave_id`, `seed_id` | `AttackResultResponse` |
| `redteam_judgments` | Optional `wave_id` filter | `JudgmentListResponse` |
| `redteam_judgment` | `wave_id`, `seed_id` | `JudgmentResponse` |
| `redteam_reflections` | — | `ReflectionListResponse` |
| `redteam_reflection` | `wave_id` | `ReflectionResponse` |
| `redteam_report` | — | Structured `ReportResponse` |
| `redteam_report_markdown` | — | Markdown `str` |
| `redteam_report_pdf` | Optional `force_regenerate` | PDF `bytes` |

For example, inspect an attack and its judgment after the run completes:

```python
attack = client.evaluations.redteam_attack(evaluation_id, "wave-id", "seed-id")
judgment = client.evaluations.redteam_judgment(evaluation_id, "wave-id", "seed-id")
report = client.evaluations.redteam_report(evaluation_id)
```

See [`RedteamStatusResponse`](/developer-guide/sdk/models-errors#redteamstatusresponse) for progress fields and terminal statuses.

## `client.harnesses`

List and manage [Harnesses](/concepts/evaluation-components/harness). `list()` combines standard and custom Harnesses.

```python
page = client.harnesses.list()
harness = client.harnesses.show("harness-id")
harness = client.harnesses.create(
    name="Custom Harness",
    agent_id="agent-id",
    persona_ids=["persona-id"],
    policy_ids=["policy-id"],
    system_prompt="Evaluate the Agent against the selected policies.",
)
harness_id = client.harnesses.resolve_custom("Custom Harness")
client.harnesses.delete("harness-id")
```

`create()` generates a [custom Harness](/developer-guide/evaluate/custom-harnesses) for an Agent. Custom Harnesses are immutable. Calling `update()` raises `NotImplementedError`; create a replacement and delete the old Harness instead.

## `client.scores`

Retrieve the latest Trust Score for an Agent, the score for a specific Evaluation, score history, or the full nested Evaluation results.

```python
latest = client.scores.show("agent-id")
score = client.scores.get("evaluation-id")
history = client.scores.history("agent-id", limit=20)
results = client.scores.results("evaluation-id")

rows = score.summarize(results=results, scale=100)
```

`show()` raises `VijilNotFoundError` when the Agent has no scores. See [Understand Evaluation Results](/developer-guide/evaluate/understanding-results) for guidance on interpreting scores.

## `client.reports`

List, fetch, and download Trust Reports. `download()` returns PDF bytes. For a Red Team report, use `client.evaluations.redteam_report()`, `redteam_report_markdown()`, or `redteam_report_pdf()`.

```python
page = client.reports.list(agent_id="optional-agent-id")
report = client.reports.show("evaluation-id")

generation = client.reports.generate("evaluation-id")
pdf_bytes = client.reports.download("evaluation-id")

with open("report.pdf", "wb") as file:
    file.write(pdf_bytes)
```

Report generation requires a team ID from the `team_id` argument, client configuration, or authenticated token. `download()` requests generation once if the PDF does not exist, then retries the download.

## `client.dome`

Read and update [Dome](/developer-guide/protect/overview) Guardrail configurations. Use [`client.protect()`](/developer-guide/sdk/lifecycle-methods#client-protect) for the high-level configuration workflow.

```python
page = client.dome.list()
config = client.dome.show("agent-id")
default_config = client.dome.default()
config = client.dome.update(
    "agent-id",
    guards=["prompt_injection"],
    mode="enforce",
)
```

## `client.jobs`

Track and control asynchronous evolution jobs.

```python
page = client.jobs.list("agent-id")
job = client.jobs.show("agent-id", "job-id")
job = client.jobs.status("agent-id", "job-id")
job = client.jobs.create("agent-id", mode="config")
job = client.jobs.cancel("agent-id", "job-id")
```

`status()` is an alias for `show()`.

## `client.genomes`

Version and compare Agent source across adaptations.

```python
page = client.genomes.list(agent_id="optional-agent-id")
genome = client.genomes.show("genome-id")
versions = client.genomes.versions("genome-id")
history = client.genomes.history("genome-id")
diff = client.genomes.diff("genome-id", v1=1, v2=3)
```

## `client.proposals`

Review and apply the adaptation proposals produced by [`client.adapt()`](/developer-guide/sdk/lifecycle-methods#client-adapt).

```python
page = client.proposals.list(agent_id="agent-id", status="pending")
proposal = client.proposals.show("proposal-id")
proposal = client.proposals.approve("proposal-id")
proposal = client.proposals.apply("proposal-id")
proposal = client.proposals.reject("proposal-id")
```

## `client.policies`

Manage the [Policies](/owner-guide/simulate-environment/policies) that constrain Agent behavior. `category` must be `privacy`, `ethics`, `security`, `compliance`, `operational`, `brand`, or `custom`.

```python
page = client.policies.list(agent_id="optional-agent-id")
policy = client.policies.show("policy-id")
policy = client.policies.create(
    name="Data Handling Policy",
    category="privacy",
    source_text="The Agent must not store or repeat personal data.",
)
policy = client.policies.update("policy-id", name="Updated Policy")
client.policies.delete("policy-id")
```

Provide policy text with `source_text` or `content`. You can also pass `file_path` to read content from a UTF-8 text file.

## `client.personas`

Manage the [Personas](/owner-guide/simulate-environment/personas) used to build custom Harnesses. Pass `role` when creating a Persona. When provided, `intent` must be `benign`, `curious`, `adversarial`, or `malicious`.

```python
page = client.personas.list(agent_id="optional-agent-id")
persona = client.personas.show("persona-id")
persona = client.personas.create(
    name="Frustrated Customer",
    role="end_user",
    intent="adversarial",
)
persona = client.personas.update("persona-id", name="Updated Persona")
client.personas.delete("persona-id")
```

## `client.monitor`

Read available Dome runtime telemetry. The `since` argument accepts durations such as `"1h"`, `"24h"`, or `"7d"`.

```python
traces = client.monitor.traces("agent-id", since="1h", limit=50)
logs = client.monitor.logs("agent-id", since="24h", limit=50)
```

<Warning>
The `summary()` and `detections()` methods currently raise `NotImplementedError` because their Console read endpoints are not available. Use `traces()` and `logs()` for supported telemetry reads.
</Warning>

## `client.agent_tunnel`

Provision or revoke the credential used to connect Vijil to a [local Agent](/developer-guide/evaluate/local-agent). `get()` creates the credential on its first call and returns the existing credential on later calls.

```python
credential = client.agent_tunnel.get()
print(credential.provider)
print(credential.binding_url)

client.agent_tunnel.revoke()
```

Treat `credential.token` as a secret. After `revoke()`, the next `get()` call provisions a new credential.

## `client.rca_runs`

Run root-cause analysis over a behavioral Evaluation's failures and retrieve the resulting engineering tickets.

```python
run = client.rca_runs.create(
    agent_id="agent-id",
    eval_id="evaluation-id",
    source_ref={"type": "github"},
    sample_size=100,
)

runs = client.rca_runs.list(agent_id="agent-id")
detail = client.rca_runs.show(run.run_id, agent_id="agent-id")

if detail.status == "completed":
    tickets = client.rca_runs.tickets(
        run.run_id,
        agent_id="agent-id",
    )
```

`create()` starts an asynchronous run and returns its ID and initial status. Poll `show()` until the status is `completed` or `failed` before requesting tickets. `source_ref` accepts a GitHub or S3 source reference.
